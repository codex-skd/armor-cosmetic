<h2>v1.0.15 - Inventory Interaction Fix</h2>

<h3>Fix</h3>
<ul>
<li><strong>Normal Inventory Interaction After Closing Cosmetic</strong>: Definitive fix for the bug where the normal inventory became unresponsive after closing the cosmetic inventory with the ✕ button. The root cause was that <code>setScreenAndShow</code> opened <code>InventoryScreen</code> on the client while the server still had the cosmetic container active, causing the server to reject slot interactions. The ✕ button now sends <code>PayloadOpenNormalInventory</code>, waits for the server to close the container (triggering <code>removed()</code>), and only then opens <code>InventoryScreen</code>. This ensures the server has released the cosmetic container before the client attempts to interact with the normal inventory.</li>
</ul>

<h3>Technical</h3>
<ul>
<li>Added <code>closeToInventory</code> flag to <code>GuiCosArmorInventory</code> to defer <code>InventoryScreen</code> opening to the <code>removed()</code> lifecycle, after the server has processed the container close.</li>
<li>Removed the immediate <code>setScreenAndShow</code> call from the ✕ button callback.</li>
</ul>

<br>

<blockquote>
This hotfix finally resolves the inventory interaction issue by properly sequencing the server container close with the client screen transition.
</blockquote>
