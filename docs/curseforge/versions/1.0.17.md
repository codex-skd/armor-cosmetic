<h2>v1.0.17 - Inventory Transition Fix (for real this time)</h2>

<h3>Fix</h3>
<ul>
<li><strong>Normal inventory unresponsive after closing cosmetic inventory</strong>: The previous attempt (v1.0.15/v1.0.16) deferred opening <code>InventoryScreen</code> to the render-state extraction phase, which still left the new screen unable to receive slot clicks. The ✕ close button now switches to <code>InventoryScreen</code> immediately in its click callback, the same pattern already used by the recipe book button, fixing item interaction right away.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li>Removed the now-unused <code>closeToInventory</code> deferred-open flag and its dead branch in <code>extractRenderState</code>.</li>
</ul>

<br>

<blockquote>
This corrects the ineffective fix shipped in v1.0.16 — closing the cosmetic inventory now reliably returns full control of the normal inventory.
</blockquote>
